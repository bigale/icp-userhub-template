## Project Overview

ICP UserHub Template — an Internet Computer (ICP) dApp with role-based access control (RBAC), Internet Identity authentication, and user profile management. Motoko backend, React + TypeScript frontend.

## Commands

### Local Development Setup
```bash
npm install
dfx start --background
dfx deps pull && dfx deps deploy   # Deploy Internet Identity dependency
dfx deploy                          # Deploy backend + frontend canisters
npm run dev                         # Vite dev server at http://localhost:5173
```

### Build & Generate
```bash
npm run generate          # Generate Candid type declarations (dfx generate backend)
npm run build             # TypeScript check + Vite production build
```

### Dev Bypass Mode (no Internet Identity popup)
Add `DEV_BYPASS_II=1` to `.env`, then use `?dev_seed=N` URL param:
- `dev_seed=0` → admin identity
- `dev_seed=1+` → regular user identities

### Port Forwarding (WSL/Docker)
```bash
CONTAINER_IP=172.17.0.2 python3 port-forward.py &
```
Forwards ports 5173 (Vite) and 4943 (dfx replica).

### Testing
No unit test framework. Uses Playwright MCP for AI-assisted E2E testing:
```bash
claude mcp add playwright npx playwright-mcp@latest
```

## Architecture

### Backend (Motoko) — `src/backend/`
- **`main.mo`** — Core actor exposing all public methods. Manages user profiles (`OrderedMap<Principal, UserProfile>`) and delegates auth to access-control module.
- **`authorization/access-control.mo`** — RBAC engine. Role hierarchy: admin > user > guest. First caller to `initialize()` becomes admin; subsequent callers get user role. `hasPermission()` checks role hierarchy.
- **`migration.mo`** — Schema migration utilities (v1→v2 added email/bio fields).

### Frontend (React + TypeScript) — `src/frontend/`
Three context layers compose the app initialization in `App.tsx`:
1. **`useInternetIdentity`** — Auth context. Manages II login/logout, dev bypass identity generation.
2. **`useActor`** — Creates `HttpAgent` + `Actor` singleton per identity. Connects to local replica (`:4943`) or mainnet.
3. **`useQueries`** — React Query hooks wrapping every backend call (`getCallerUserProfile`, `assignUserRole`, etc.).

### Candid Type Bridging — `src/frontend/src/backend.ts`
Motoko optionals encode as `[] | [T]` in Candid. `toCandidProfile()` and `fromCandidProfile()` convert between Candid arrays and TypeScript `?` optionals.

### UI Stack
- Vite bundler, Tailwind CSS with OKLCH color system, shadcn/ui components
- Path alias: `@/` → `src/frontend/src/`
- Env var prefixes exposed to Vite: `CANISTER_*`, `DFX_*`, `DEV_*`

### Key Data Flow
```
Internet Identity → useInternetIdentity (identity)
  → useActor (HttpAgent + Actor)
    → useQueries (React Query hooks)
      → Components (Dashboard, ProfileTab, UsersTab)
```

### Canister Configuration — `dfx.json`
- `internet_identity`: Pulled from mainnet (`rdmx6-jaaaa-aaaaa-aaadq-cai`)
- `backend`: Motoko actor at `src/backend/main.mo`
- `frontend`: Asset canister serving `src/frontend/dist`
- Environment variables generated to `.env` via `output_env_file`

## Important Patterns

- **Authorization**: All backend methods check permissions via `hasPermission()` and trap on denial. Admin-only operations: `getAllUserProfiles`, `assignCallerUserRole`, `getUserProfile` (for other users).
- **React Query**: All backend data fetched/mutated through React Query hooks in `useQueries.ts`. Queries are `enabled` only when actor is ready. Cache invalidation triggers re-fetch after mutations.
- **Generated files**: `src/frontend/src/declarations/` is generated by `dfx generate` — do not edit manually. The `.env` file is generated by `dfx deploy`.
